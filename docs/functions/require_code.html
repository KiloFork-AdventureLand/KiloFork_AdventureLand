require_code(name_or_slot)

Synchronously evaluates a code slot or local code file in module scope and returns module.exports.

Returns: Exports object or any value assigned to module.exports.

Exports: The loaded file must explicitly assign module.exports or add properties to exports. Local declarations alone are not exported. Assigning exports = value does not replace module.exports. JavaScript import and export declarations are not supported.

No module cache: Every call executes the file again, including nested calls from other modules. Objects created by separate executions are separate copies, and initialization can create duplicate timers or listeners. Require once and pass the returned value to callers that need the same object.

No circular dependencies: A requiring B while B requires A keeps loading recursively until an error or execution limit stops it. Put shared values in a module that does not require its callers.

These rules also apply on Mainframe. Module scope still allows access to existing game globals. Use load_code when global declarations are intentional. See Code Slots and Files for a complete dependency example.

Example:

Save this in a numbered slot named Constants:

const TARGET = "goo"; module.exports = { TARGET };

Run this from your character slot:

var constants = require_code("Constants"); game_log(constants.TARGET); // goo
