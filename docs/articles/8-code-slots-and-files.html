CODE slots and files

Each character has a default CODE slot. When you run changed CODE in the in-game editor, the client saves that slot to the game server.

Your account also has numbered CODE slots from 1 to 100. Use them for shared helpers, combat loops, merchant logic, or experiments that more than one character can load.

Character slots use the character's internal ID as their slot number. Numbered slots use the number you see in the editor.

show_json(X.codes); // Slot names and IDs available to this account

Loading shared CODE

Keep the character's default slot small when possible. Put reusable functions in numbered slots, then load them from the character slot.

Both load_code and require_code run the file immediately and wait for its synchronous code to finish. Every call executes the file again, including calls made by other loaded files. Avoid loading files inside a repeating combat loop.

Global scripts: load_code

load_code runs a file in the character's global CODE scope, even when called inside a function or a module. Its top-level declarations become available to other CODE in that character.

Loading the same file again can cause an Identifier has already been declared error for top-level const, let, or class declarations. Repeating var declarations can reset values. Any initialization that runs again can also create duplicate timers or event listeners.

For scripts that use globals, load dependencies once from the character slot, before the files that use them. For example, if saved slots named Constants, Combat, and Merchant define globals, start with:

load_code("Constants"); load_code("Combat"); load_code("Merchant");

In this arrangement, Combat and Merchant use the globals from Constants; they should not load Constants again.

Modules: require_code

require_code gives the loaded file its own scope and returns module.exports. Declare local variables with const, let, or var, and explicitly export what callers need. Changing only load_code to require_code does not export existing declarations: a file with no exports returns an empty object.

Use module.exports = value to return a value, or add properties such as exports.TARGET = "goo". Assigning a new object to exports alone does not replace module.exports. These loaders do not support JavaScript import and export declarations.

No module cache: each call evaluates the file again. If two modules require Constants, Constants runs twice. Objects created by those executions are separate copies, and initialization runs twice too. If callers need the same object, require it once and pass the returned value to them.

No circular dependencies: a chain such as A requiring B, then B requiring A, keeps loading recursively until an error or execution limit stops it. Move shared values into a third module that does not require either caller.

These repeated-loading rules also apply on Mainframe. Module scope does not prevent a file from using existing game globals or deliberately changing global state.

VS Code sync

Type /codes in chat or open adventure.land/vscode. The VS Code extension creates a local sync folder and uploads through your account token.

Name local files with the slot number before .js:

Wizard.482008842.js // A character default slot Farming.12.js // Account CODE slot 12

Run Adventure Land: Activate Auto Sync Folder once. It downloads your CODE slots, refreshes helper libraries, checks for remote changes, uploads safe offline edits, and uploads managed files when you save them.

CODE example: shared module dependencies

Save Constants, Combat, and Merchant in three separate numbered slots. Put the final block in your character slot. This example uses modules; run it separately from the global example above.

Constants

const TARGET = "goo"; const BANK_MAP = "bank"; module.exports = { TARGET, BANK_MAP };

Combat

const constants = require_code("Constants"); module.exports = { target_type: constants.TARGET };

Merchant

const constants = require_code("Constants"); module.exports = { bank_map: constants.BANK_MAP };

Character slot

var combat = require_code("Combat"); var merchant = require_code("Merchant"); game_log(combat.target_type); // goo game_log(merchant.bank_map); // bank

The character slot requires Combat and Merchant; each requires Constants. This works because Constants only declares and exports values. It still executes twice. Keep timers, listeners, and other startup work out of a repeatedly required constants module.
